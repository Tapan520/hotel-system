# Architecture

## Tech Stack
| Layer | Technology |
|-------|-----------|
| Runtime | .NET 8 / ASP.NET Core |
| Language | C# 12 |
| ORM / DB Access | Raw SQL via **MySql.Data** (Dapper-style — no EF Core) |
| Database | MySQL 8 |
| Auth | JWT Bearer — `Microsoft.AspNetCore.Authentication.JwtBearer` |
| Password hashing | BCrypt.Net-Next |
| JSON serialisation | **Newtonsoft.Json** with `CamelCasePropertyNamesContractResolver` |
| Frontend | Vanilla HTML5 / JS (no framework) |
| Hosting | Railway (Docker) |

## Project Structure Philosophy
- **One file per concern layer**: all controllers in `Controllers.cs`, all models in `Models.cs`, all DTOs in `DTOs.cs`.  
- **DatabaseService.cs** is the single data-access class (~2 k lines). Every database query lives there.  
- **AuthService.cs** handles only JWT generation and BCrypt operations.

## Middleware Pipeline Order (Program.cs)
```
Swagger ? UseDefaultFiles ? UseStaticFiles ? UseCors ? UseAuthentication ? UseAuthorization ? MapControllers
```
- `UseDefaultFiles` must come before `UseStaticFiles` so `/` resolves to `index.html`.
- Static files (HTML) are served on the **same port** as the API — no separate web server.
- CORS policy `HotelCors` = AllowAnyOrigin / AllowAnyMethod / AllowAnyHeader.  
  **Do NOT add `AllowCredentials()`** — incompatible with `AllowAnyOrigin`.

## Authentication Flow
1. `POST /api/auth/login` ? returns `{ success, data: { token, role, fullName, hotelId } }`.
2. All subsequent requests send `Authorization: Bearer <token>`.
3. JWT claims include: `NameIdentifier` (UserId), `Name` (Username), `Role`, `HotelId`, `Email`.
4. **Customer Portal** uses a separate JWT role `"Customer"` generated by `GenerateCustomerToken()`.
5. Invalid JWT ? 401 JSON (handled by `OnChallenge` event — never returns HTML).
6. Forbidden ? 403 JSON (handled by `OnForbidden` event).

## Roles (least ? most privileged)
```
Customer  ?  FrontDesk  ?  Finance  ?  Reservations  ?  HotelAdmin  ?  SuperAdmin
```

## Database Access Pattern
- `DatabaseService` is registered as **Singleton**.
- Every method opens a new `MySqlConnection`, executes, closes — no connection pooling abstraction beyond MySql.Data's built-in pool.
- No transactions except where explicitly coded with `MySqlTransaction`.
- Stored procedures are used for complex operations: `sp_CreateBooking`, `sp_CancelBooking`, `sp_CreateOrder`, `sp_BillOrder`, `sp_QuickBillDirectSale`, `sp_DeductRecipeStock`, `sp_GenerateCheckoutInvoice`.
- Views used: `vw_Bookings`, `vw_OrderDetails`.

## JSON Serialisation
- **camelCase** everywhere — enforced by `CamelCasePropertyNamesContractResolver`.
- `NullValueHandling.Ignore` — null fields are omitted from responses.
- `DateFormatString = "yyyy-MM-dd'T'HH:mm:ss"`.
- All API responses are wrapped in `ApiResponse<T>`: `{ success, message, data, totalCount?, errorCode?, timestamp }`.

## Port Handling
- Railway injects `PORT` env var at runtime.
- `Program.cs` reads it: `app.Run($"http://0.0.0.0:{port}")`.
- Local dev defaults to port `5000`.
