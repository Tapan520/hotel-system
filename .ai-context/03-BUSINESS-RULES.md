# Business Rules

## Booking Lifecycle
```
Confirmed ? CheckedIn ? CheckedOut
         ? Cancelled (from Confirmed only)
```
- Booking reference format: `BK{yyyyMMdd}{random8digits}` (generated by `sp_CreateBooking`).
- A booking can only be checked in if status = `Confirmed`.
- A booking can only be checked out if status = `CheckedIn`.
- Cancellation triggers a **cancellation charge** based on hotel's `CancellationPolicyHours` and `LateCancelChargePercent`.

## Pricing / Rate Logic
1. **Per-date rates** (`roomrates` table) take priority over default rates.
2. If no per-date rate exists, fall back to `defaultroomrates` (weekday vs weekend).
3. Weekend = Saturday and Sunday.
4. Channel partner `MarkupPercent` is added on top of the room rate.
5. Hotel tax (`TaxPercent`, default 12%) is applied to `SubTotal + AddonTotal`.
6. `GrandTotal = SubTotal + AddonTotal + TaxAmount - DiscountAmount`.
7. `NetToHotel = GrandTotal - CommissionAmount`.
8. Admin can override rate via `OverrideRoomRate` field in `CreateBookingRequest`.

## Booking Add-ons Charge Types
| ChargeType | How quantity is computed |
|-----------|--------------------------|
| `PerStay` | × 1 (fixed per booking) |
| `PerNight` | × number of nights |
| `PerPerson` | × adults count |
| `PerPersonPerNight` | × adults × nights |

## Availability Logic
- `RoomAvailability.AvailableRooms = TotalRooms - BlockedRooms - BookedRooms` (computed property).
- `sp_CreateBooking` decrements `BookedRooms` on successful booking.
- `sp_CancelBooking` increments `BookedRooms` back on cancellation.
- Admin can manually block/unblock via `/api/availability/block` and `/api/availability/unblock`.

## Order Management System (OMS)
### Order Types
| Type | Description |
|------|-------------|
| `InRoom` | Linked to a hotel room booking; `BookingId` is required |
| `DirectSale` | Restaurant/bar walk-in; `WalkInGuestName` is required |

### Order Status Flow
```
Pending ? InProgress ? Delivered ? Billed
        ? Cancelled (any stage before Billed)
```
- When status changes to `Delivered`, **recipe stock is auto-deducted** via `sp_DeductRecipeStock`.
- If stock is insufficient, status still updates but response contains prefix `INVENTORY_WARNING:`.
- `Billed` = order has been posted to the booking folio or issued a direct sale receipt.
- `QuickBill` = single-step shortcut (Delivered + Billed) for DirectSale orders.

### Folio (Guest Bill)
- Every charge against a booking is a `BillEntry` row.
- `BillEntry.EntryType` can be: `RoomCharge`, `OrderCharge`, `ManualCharge`, `AddonCharge`, etc.
- Entries can be **voided** (soft-delete with reason) — never hard-deleted.
- `CheckoutInvoice` is generated at checkout and consolidates all folio lines.

## Recipe-Based Inventory (RIMS)
- Each `Recipe` is linked to an `OrderCatalogItem` via `CatalogId`.
- When a recipe is created/updated, its `SellingPrice` is **synced to the linked catalog item** automatically.
- Stock deduction: when an order item is delivered, the system looks up the recipe by `CatalogId` and deducts `RecipeIngredient.Quantity × portions` from `InventoryItem.CurrentStock`.
- `Recipe.MaxPortions` = `floor(CurrentStock / QuantityPerYield)` across all ingredients (minimum).
- `Recipe.BottleneckIngredient` = the ingredient with the lowest `MaxPortions`.
- `IsLowStock` on `InventoryItem` = `CurrentStock <= MinStockLevel`.

## Customer Profile
- Customers are identified by email. If a customer with the same email already exists during booking creation, the existing record is reused (upsert logic in `sp_CreateBooking`).
- `TotalStays` is incremented on checkout.
- `VIPStatus`: `Regular | Silver | Gold | Platinum`.

## User Account Security
- Passwords hashed with **BCrypt** (cost factor default).
- Failed login increments `LoginAttempts`; account locks via `LockedUntil`.
- `MustChangePass` flag forces password change on next login.
- Only `SuperAdmin` can reset another user's password.

## Currency
- Default currency: **INR (?)**.
- `CurrencyCode` is stored per hotel and included in booking responses.
